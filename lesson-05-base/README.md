# فایل‌های همراه درس 5: پروژهٔ پایهٔ STM32F303

این بسته شامل یک پروژهٔ واقعی برای STM32F303CBT6 روی GB100ST V2.0 است. پروژه با CubeMX 6.14.0 و بستهٔ F3 نسخهٔ 1.11.6 تولید و با GCC 13.2.1 در مسیر CMake Debug با `-Wall -Werror` بدون هشدار ساخته شده است. اجرای CubeIDE، پروگرام و آزمون روی برد انجام نشده است.

## تنظیمات واقعی

SYSCLK و HCLK از HSI با 8 MHz تأمین می‌شوند؛ PLL انتخاب نشده است. PA13/PA14 برای SWD و PB6 برای USER_LED با سطح اولیهٔ Low رزرو شده‌اند. کریستال HSE برد 8 MHz و LSE برابر 32.768 kHz است. پایه‌های PF0/PF1 و PC14/PC15 در IOC به حالت کریستالی اختصاص یافته‌اند، اما چون در این پروژه مصرف‌کنندهٔ کلاک آن‌ها انتخاب نشده، CubeMX در SystemClock_Config تنها HSI را راه‌اندازی کرده است. رزرو پایه و ورود مقدار نامی، شاهد روشن‌بودن نوسان‌ساز نیست. پیکربندی HSE و PLL برای 72 MHz در درس 9 و استفاده از LSE برای RTC در درس مربوط انجام می‌شود.

Timebase پیش‌فرض HAL از SysTick با تیک 1 ms است. برای HCLK = 8 MHz، پارامتر SysTick_Config برابر 8000 و مقدار مورد انتظار LOAD برابر 7999 است. این مقدار محاسبه شده و روی برد اندازه‌گیری نشده است.

## فایل‌ها و اجرا

- `lesson-05-project.zip`: منابع کامل، IOC، HAL/CMSIS و مجوزهای اصلی؛ فاقد پوشهٔ موقت build.
- `toolchain-and-validation.json`: نسخه‌ها، تنظیمات و SHA256 فایل‌های اصلی منبع.
- `source-evidence.txt`: قطعه‌های واقعی تولیدشده و درایور، و حدود سناریوی خطا.
- `build-report.txt`: گزارش واقعی ساخت پاک و اندازه‌های ناحیه‌های لینک.
- `verify_timebase.py` و `timebase-results.json`: محاسبهٔ مستقل Python 3؛ اجرا با `python verify_timebase.py` پس از استخراج بستهٔ منابع.
- فایل‌های PNG: نمودارهای تألیفی؛ تصویر واقعی نرم‌افزار یا آزمایش نیستند.

برای ساخت، ZIP پروژه را استخراج و در محیط دارای CMake 3.22 یا جدیدتر، Ninja و arm-none-eabi-gcc از ریشهٔ پروژه اجرا کنید:

```text
cmake --preset Debug
cmake --build --preset Debug --clean-first
```

برای مسیر گرافیکی CubeIDE، ابتدا از IOC نسخهٔ جدا بگیرید و در CubeMX خروجی STM32CubeIDE تولید کنید. بستهٔ حاضر خروجی آزمایش‌شدهٔ CMake است و متادیتای Eclipse ندارد. پس از هر تولید مجدد وجود `-Wall -Werror` و انتخاب نسخهٔ بستهٔ F3 را بررسی کنید. فایل IOC نیز باید در کنترل نسخه نگهداری شود؛ گزینهٔ Keep User Code جای پشتیبان‌گیری را نمی‌گیرد. در این پروژه LastFirmware=false برای انتخاب نسخهٔ مشخص بسته نگه داشته شده است.

مصرف ناحیهٔ RAM گزارش‌شده 1584 بایت شامل 12 بایت داده، 36 بایت BSS و رزرو حداقل heap و stack برابر 512 و 1024 بایت است؛ این عدد اندازه‌گیری مصرف هنگام اجرا نیست. Flash گزارش‌شده 7964 بایت است.

مجوزهای اصلی ST و Arm در Drivers حفظ شده‌اند. اطلاعات ورود، حافظهٔ موقت ساخت و فایل‌های تنظیمات شخصی در بستهٔ عمومی قرار نگرفته‌اند.
