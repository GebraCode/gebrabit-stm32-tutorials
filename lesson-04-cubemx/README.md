# فایل‌های همراه درس 4: ایجاد پروژه با STM32CubeMX

پروژهٔ واقعی برای STM32F303CBT6 روی برد GB100ST V2.0 تولید و با GCC/CMake به صورت clean و با `-Wall -Werror` بدون هشدار ساخته شده است. آزمایش روی برد و اجرای CubeIDE انجام نشده است.

## محتوا

- `lesson-04-resources.zip`: بستهٔ کامل همهٔ فایل‌های همراه؛ ابتدا این بسته را استخراج کنید تا پوشهٔ شواهد برای اسکریپت بررسی در دسترس باشد. سپس پروژهٔ داخل `lesson-04-project.zip` را جداگانه استخراج کنید.
- `lesson-04-project.zip`: پروژهٔ کامل شامل `.ioc`، منابع تولیدشده، HAL/CMSIS و مجوزهای اصلی؛ بدون حافظهٔ موقت ساخت.
- `build-report.txt`: گزارش ساخت واقعی با GCC 13.2.1.
- `toolchain-and-validation.json`: نسخه‌ها، منشأ کتابخانه، محدودیت اعتبارسنجی و تنظیمات واقعی.
- `regeneration-evidence/`: دو تصویر متنی واقعی از main.c پیش و پس از تولید مجدد.
- `verify_regeneration.py`: بررسی حفظ دو بخش USER CODE و حذف توضیح خارج آن‌ها، بدون نیاز به کتابخانهٔ جانبی پایتون.

## تنظیمات

HSI برابر 8 MHz، بدون PLL؛ PA13 و PA14 برای SWD؛ PB6 خروجی USER_LED با سطح اولیهٔ Low و سرعت Medium. پیکربندی استاندارد 72 MHz دوره در درس 9 آموزش داده می‌شود. این پروژه هنوز برنامهٔ چشمک‌زن نیست؛ متغیر lesson4_marker فقط ساختار نگهداری کد را نشان می‌دهد.

## ساخت بازتولیدپذیر

در محیط دارای CMake 3.22 یا جدیدتر، Ninja و arm-none-eabi-gcc، از ریشهٔ پروژه اجرا کنید:

```text
cmake --preset Debug
cmake --build --preset Debug --clean-first
```

برای مسیر CubeIDE، فایل `.ioc` را در CubeMX مستقل باز کنید، Toolchain/IDE را STM32CubeIDE انتخاب و در پوشه‌ای جدا کد تولید کنید؛ سپس پروژهٔ تولیدشده را در Workspace وارد کنید. فایل همراه خروجی CMake است و نباید به عنوان پروژهٔ آزمایش‌شدهٔ CubeIDE معرفی شود. CubeMX ممکن است فایل toolchain را هنگام تولید مجدد بازنویسی کند؛ وجود `-Wall` و `-Werror` را پیش از ساخت دوباره بررسی کنید.

## آزمایش نگهداری کد

در نسخهٔ پیش از تولید مجدد، اعلان `volatile uint32_t lesson4_marker = 0U;` داخل USER CODE PV و دستور `lesson4_marker = 1U;` داخل USER CODE 2 قرار گرفت. توضیحی با شناسهٔ LESSON4_OUTSIDE_USER_CODE بعد از END 2 قرار داده شد. سپس سرعت PB6 از Low به Medium تغییر کرد و CubeMX واقعاً دوباره اجرا شد. دو عبارت حفاظت‌شده باقی ماندند و توضیح بیرون حذف شد.

```text
python verify_regeneration.py
```

حذف توضیح خارج بلوک، نتیجهٔ همین آزمایش روی main.c است؛ به معنای حذف اجباری هر فایل یا هر تغییر بیرون USER CODE در تمام حالت‌های CubeMX نیست. نسخه‌گذاری و پشتیبان ضروری است.

## مجوز

مجوز اصلی ST و Arm در زیرپوشه‌های Drivers حفظ شده است. مالکیت فایل‌های تولیدشده به صاحبان اصلی تعلق دارد؛ منابع رسمی قابل دسترسی از STMicroelectronics/STM32CubeF3 هستند. در این بسته اطلاعات ورود یا فایل تنظیمات شخصی منتشر نشده است.
