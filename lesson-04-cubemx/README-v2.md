# درس4: یک پروژهٔ حداقلی و آزمایش تولید دوباره

این پروژه برای STM32F303CBT6 روی GB100ST V2.0 ساخته شده است. هنوز برنامهٔ چشمک‌زن یا خروجی GPIO ندارد. هدف، شناخت فایل‌های پروژه و محل امن کد کاربر است؛ متغیر lesson4_marker فقط برای این آزمایش استفاده می‌شود.

## از کجا شروع کنیم؟

1. بستهٔ کامل منابع را استخراج کنید. سپس lesson-04-project-v2.zip را باز کنید؛ پروژهٔ نهایی داخل پوشهٔ gebrabit_lesson04_cubemx_v2 است.
2. فایل IOC را با CubeMX مستقل باز کنید. تراشه، Pinout و Project Manager را ببینید. کلاک این درس HSI داخلی با مقدار اسمی8MHz است؛ تنظیم72MHz در درس9 می‌آید.
3. برای ساختِ مسیر بررسی‌شده، GCC13.2.1، CMake3.22 یا جدیدتر و Ninja باید در PATH باشند. از ریشهٔ پروژه اجرا کنید:

```text
cmake --preset Debug
cmake --build --preset Debug --clean-first
```

این بسته خروجی واقعی CMake است. فایل‌های native مانند .project/.cproject مربوط به CubeIDE در آن نیستند. برای مسیر CubeIDE2.x، در CubeMX مستقل Toolchain/IDE را STM32CubeIDE انتخاب کنید و در یک پوشهٔ جدا خروجی بسازید؛ سپس پروژهٔ تولیدشده را با Import / Existing Projects into Workspace وارد کنید. نام منو با نسخه می‌تواند فرق کند. تولید این خروجی، واردکردن، ساخت و اجرای CubeIDE در این کار انجام نشده است؛ موفقیت ساخت CMake را شاهد آزمون CubeIDE ندانید.

## چه چیزی تولید شده است؟

- Core/Src و Core/Inc: برنامه، سرآیندها و توابع مقداردهی.
- Drivers: کتابخانه‌های HAL/CMSIS با مجوزهای اصلی.
- IOC: تنظیم‌های CubeMX؛ CMakeLists.txt و cmake/: مسیر ساخت این بسته.
- فایل linker با پسوند ld: ناحیه‌های حافظه و رزروهای حداقلی heap/stack.

PA13 و PA14 برای SWD باقی مانده‌اند. GPIO output، LED، UART، ADC و تایمر کاربردی تنظیم نشده‌اند. gpio.c فقط کلاک GPIOA را فعال می‌کند و هیچ پایه‌ای را با HAL_GPIO_Init مقداردهی نمی‌کند. مقدارهای HSE/LSE موجود در IOC به معنی استفاده از آن‌ها در کلاک این پروژه نیستند.

Project Manager دارای Keep User Code=true، Backup Previous=true و تولید فایل جدا برای هر پریفرال (CoupleFile=true) است. Firmware روی CubeF3V1.11.6 ثابت شده و LastFirmware=false است. همیشه نسخهٔ پشتیبان یا کنترل نسخه داشته باشید؛ USER CODE جای پشتیبان را نمی‌گیرد.

## آزمایش واقعی تولید دوباره

نسخهٔ پیش از بازتولید، heap حداقلی0x200 داشت. داخل main.c/USER CODE PV عبارت volatile uint32_t lesson4_marker = 0U و داخل USER CODE2 دستور lesson4_marker = 1U قرار گرفت. یک توضیح آزمایشی با نام LESSON4_OUTSIDE_USER_CODE_V2 بلافاصله بیرون END2 اضافه شد. آن توضیح، شیوهٔ پیشنهادی نوشتن کد نهایی نیست؛ فقط نشانهٔ قابل حذف برای یک آزمایش کنترل‌شده است.

سپس تنظیم HeapSize در Project Manager از0x200 به0x300 تغییر کرد و CubeMX واقعاً دوباره اجرا شد. دو عبارت داخل USER CODE حفظ شدند و توضیح بیرون بلوک حذف شد. در linker نیز رزرو heap از512 به768 بایت تغییر کرد. این نتیجه مخصوص همین فایل تولیدشده و همین تنظیم‌هاست؛ به معنی پاک‌شدن همهٔ فایل‌ها یا همهٔ تغییرهای خارج USER CODE در هر پروژه نیست. تابع تولیدشده‌ای مثل SystemClock_Config را دوباره تعریف نکنید.

فایل‌های قبل/بعد، diff و هش‌ها در regeneration-evidence هستند. برای بررسی قابل تکرار، پس از استخراج بستهٔ کامل اجرا کنید:

```text
python verify_regeneration.py
```

اسکریپت فایل‌های ثبت‌شده و محاسبات حافظه را بررسی می‌کند؛ CubeMX را دوباره اجرا یا سخت‌افزار را شبیه‌سازی نمی‌کند. برای تکرار کامل تولید، ابتدا از پروژه کپی بگیرید، markerهای قبل و تنظیم0x200 را در نسخهٔ آزمایشی بازسازی کنید، تنظیم را به0x300 برگردانید و Generate Code بزنید. پیش از ساخت، گزینه‌های هشدار را دوباره کنترل کنید؛ generator ممکن است فایل toolchain را بازنویسی کند.

## نتیجه و محدودیت بررسی

هر دو نسخهٔ قبل و بعد واقعاً clean ساخته شدند: Debug با -O0 -g3 -Wall -Werror و صفر هشدار. Flash هر دو7052B است. RAM گزارش linker از1584B به1840B تغییر کرده است: data12 + bss عادی36 + حداقل stack1024 + heap512 یا768. افزایش256B مربوط به رزرو linker است، نه اندازه‌گیری مصرف واقعی حافظه یا اجرای malloc.

CubeMX6.14.0، DB6.0.140، STM32CubeF3V1.11.6 با commit663d2baae3604244f90ed80d0d757df17e36ada9 و HAL953955afe65f89e60e556bbcdba752597f5da65d استفاده شده‌اند. کامپایلر arm-none-eabi-gcc13.2.1 20231009 است. build-report-before/after و toolchain-and-validation.json جزئیات و هش‌ها را دارند. lesson-04-build-artifacts-v2.zip حاوی ELF/MAP واقعی هر دو مرحله است. فقط پروژهٔ بعد از تغییر، نسخهٔ نهایی سورس است.

اجرای روی برد، مشاهدهٔ مقدار marker در دیباگر، پروگرام، CubeIDE GUI و اندازه‌گیری کلاک انجام نشده‌اند. این پروژه خروجی دیداری روی LED ندارد. جدول worksheet برای آزمون‌های انجام‌نشده همراه است.

## منابع و مجوز

راهنمای CubeMX، UM1718، مرجع گزینه‌های تولید است. قالب رسمی بررسی‌شده در CubeF3 مسیر Projects/STM32303C_EVAL/Templates/Src/main.c است: الگوی HAL_Init، SystemClock_Config و حلقهٔ اصلی را نشان می‌دهد، اما برای برد دیگر و کلاک72MHz است؛ کلاک آن در این درس کپی نشده است. کد معرفی‌شده به عنوان تولید CubeMX از همین پروژهٔ واقعی استخراج شده است.

مجوزهای ST و Arm در Drivers حفظ شده‌اند. فایل‌های شخصی، cache ساخت و Backupهای خودکار داخل ZIP سورس نیستند؛ قبل/بعد آزمایش عمداً در پوشهٔ شواهد جدا ارائه شده‌اند.
