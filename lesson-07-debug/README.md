# فایل‌های همراه درس 7: دیباگ مقدماتی

این بسته پروژهٔ واقعی و دارای خطای منطقی عمدی برای STM32F303CBT6 روی GB100ST V2.0 است. چهار متغیر volatile با نام‌های step_count، event_count، observed_value و trace_dropped برای مشاهده در دیباگر وجود دارند. متغیر محلی derived نیز برای بررسی اثر بهینه‌سازی نگهداری شده است؛ قابلیت نمایش آن در هر نقطه و هر تنظیم تضمین نشده است.

## پروژه‌ها و خطای عمدی

`lesson-07-projects.zip` دو پروژهٔ منبع دارد: gebrabit_lesson07_debug با LESSON7_FIXED=0 و gebrabit_lesson07_fixed با LESSON7_FIXED=1. تنها تفاوت main.c این دو، مقدار پیش‌فرض همین ماکرو است. شرط اولیه step_count > 10U و شرط اصلاح‌شده step_count >= 10U است. پس از افزایش شمارنده، observed_value از step_count*2 ساخته می‌شود؛ در رخداد، شمارندهٔ رخداد افزایش یافته، step_count صفر و LED روی PB6 Toggle می‌شود و یک نویسهٔ E برای خروجی trace تلاش می‌شود. پایان هر دور HAL_Delay(100U) است.

پیش‌بینی محاسباتی: نخستین رخداد برنامهٔ دارای باگ در دور 11، observed_value برابر22 و step_count پس از بدنه صفر است. در برنامهٔ اصلاح‌شده نخستین رخداد در دور10 و observed_value برابر20 است. این‌ها پیش‌بینی مدل‌اند و مشاهدهٔ دیباگر یا برد نیستند. خود برنامهٔ اولیه را با دیباگر بررسی کنید و پیش از مشاهدهٔ پاسخ، نتیجهٔ خود را در کاربرگ ثبت کنید.

## ساخت و شواهد واقعی

CubeMX6.14.0، DB6.0.140، STM32CubeF3V1.11.6 و GCC13.2.1 استفاده شده‌اند. سه ساخت پاک با -Wall -Werror بدون هشدار انجام شد: برنامهٔ دارای باگ با -O0 -g3 و -Og -g3، و برنامهٔ اصلاح‌شده با -O0 -g3. تنظیم مقایسهٔ -Og در همین پروژه به‌صورت صریح برای RelWithDebInfo تعیین شده؛ این نام به معنی تغییر پیش‌فرض همهٔ ابزارها نیست و Release استاندارد این پروژه دست‌نخورده است. Debug دارای باگ Flash8284/RAM1600 و مقایسهٔ Og Flash4408/RAM1600 و Debug اصلاح‌شده Flash8284/RAM1600 بایت است. RAM ناحیهٔ لینک شامل رزرو پشته و heap است و مصرف لحظه‌ای اجرا نیست.

ZIP خروجی‌ها شامل ELF و MAP واقعی برای هر 3 ساخت است؛ build-comparison.csv، گزارش‌های ساخت و toolchain-and-validation.json اندازه و هش‌ها و فرمان واقعی کامپایل را دارند.

برای ساخت پس از استخراج منابع، در محیط دارای CMake3.22 یا جدیدتر، Ninja و arm-none-eabi-gcc، از ریشهٔ پروژه اجرا کنید:

```text
cmake --preset Debug
cmake --build --preset Debug --clean-first
cmake --preset RelWithDebInfo
cmake --build --preset RelWithDebInfo --clean-first
```

برای نسخهٔ اصلاح‌شده همین دستورهای Debug را از ریشهٔ پروژهٔ fixed اجرا کنید. ابزار CMake هنگام ساخت، فایل‌های متنی objdump disassembly، nm symbols و DWARF را نیز ایجاد می‌کند. آن فرمان‌ها در ساخت سرور اجرا شدند، اما سرور فایل‌های موقت متنی را در دانلود نگه نداشت؛ بستهٔ فعلی فقط ELF و MAP را از آن مرحله دارد. elf-inspection.json گزارش مستقل تحلیل فرادادهٔ ELF با inspect_elf.py است؛ اسکریپت با کتابخانهٔ استاندارد Python3 سه ELF داخل ZIP را می‌خواند و واقعاً اجرا شده است. وجود بخش‌های debug و نمادهای سراسری را نشان می‌دهد؛ محل متغیرهای بهینه‌شده را از DWARF رمزگشایی نمی‌کند و لاگ GDB یا برد نیست.

```text
python verify_bug.py
python inspect_elf.py
```

## SWD و خروجی اختیاری SWO

کلاک واقعی پروژه HSI با8MHz است. SWDIO رویPA13، SWCLK رویPA14 و SWO رویPB3 است؛ پایه‌های کریستال HSE/LSE فقط رزرو شده‌اند. برنامه PB3 را به خروجی GPIO عادی تبدیل نمی‌کند. پروگرامر باید واقعاً SWO را پشتیبانی کرده و پایهٔ مربوط را در دسترس قرار دهد؛ وجود دو پایهٔ SWD به‌تنهایی شاهد پشتیبانی از SWO نیست.

در CubeIDE، راه‌اندازی نشست دیباگ و مشاهدهٔ SWV/ITM به‌صورت راهنما آموزش داده می‌شود؛ نشست GUI روی کامپیوتر ما اجرا نشده است. پس از اتصال اختیاری PB3 به SWO پروگرامر، کلاک هستهٔ ثبت‌شده برای SWV باید8MHz و پورت محرک ITM برابر0 باشد و مسیر trace توسط دیباگر پیکربندی شود. راهنمای پروگرامر خود را برای اتصال و پشتیبانی بررسی کنید.

Trace_TryPutChar کد کاربر داخل USER CODE4 است. این تابع تنها اگر TRCENA و ITMENA و پورت0 فعال و خروجی آماده باشد، نویسه را می‌نویسد؛ در غیر این صورت trace_dropped را افزایش می‌دهد. حلقهٔ انتظار و printf ندارد و خودش قفل‌های trace یا TPIU را فعال نمی‌کند. این مسیر UART استفاده نمی‌کند. در نبود trace خروجی خالی طبیعی است و برنامه منتظر اتصال ابزار نمی‌ماند.

برنامهٔ دارای باگ و اصلاح‌شده کامپایل شده‌اند؛ هیچ پروگرام، اجرای برد، مشاهدهٔ زندهٔ رجیستر یا دیباگ واقعی و دریافت SWO انجام نشده است. کاربرگ debug-worksheet.csv عمداً وضعیت درانتظار دارد. توقف روی Breakpoint زمان‌بندی را تغییر می‌دهد؛ این برنامه ISR کاربری ندارد و نباید ایجاد رخداد یا اندازه‌گیری زمان آن را به‌عنوان آزمون ISR معرفی کرد.

## مجوز

مجوزهای اصلی ST و Arm در Drivers حفظ شده‌اند. پروژه‌های عمومی فاقد کلید، اطلاعات ورود و حافظهٔ موقت ساخت‌اند. برای مسیر CubeIDE ابتدا از IOC کپی جدا بگیرید و در CubeMX خروجی مناسب IDE تولید کنید؛ بستهٔ فعلی خروجی واقعاً بررسی‌شدهٔ CMake است.
