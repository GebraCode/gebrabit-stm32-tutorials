# مسیر کلاک را از ورودی تا PA8 دنبال کنیم

از فایل `lesson-09-projects-v2.zip` فقط نمونهٔ مورد نیاز را استخراج کنید. هر پروژه منابع و IOC کامل خودش را دارد؛ پروژه‌ها را روی هم کپی نکنید.

- `gebrabit_lesson09_hsi`: منبع هسته HSI با 8 MHz و MCO مستقیم HSI با 8 MHz؛ دورهٔ اسمی 125 ns.
- `gebrabit_lesson09_clock`: قالب دوره از این درس؛ HSE برابر 8 MHz، PREDIV برابر 1، PLL برابر 9، SYSCLK/HCLK برابر 72 MHz، APB1 برابر 36 MHz و APB2 برابر 72 MHz، Flash برابر 2 WS. MCO از منبع PLL/2 با فرکانس اسمی 36 MHz است.
- `gebrabit_lesson09_hse_mco`: همان هستهٔ 72 MHz، ولی MCO از HSE با 8 MHz؛ برای مقایسه با خروجی HSI در فرکانس اسمی یکسان.

این تراشه مقسم عمومی MCOPRE ندارد؛ /16 را به آن نسبت ندهید. PLL/2 یک انتخاب منبع ثابت است و RCC_MCODIV_1 باقی می‌ماند. پایهٔ PA8 ابتدا در IOC خروجی GPIO با مقدار Low است و فراخوانی واقعی HAL_RCC_MCOConfig در USER CODE 2، بعد از MX_GPIO_Init، آن را به AF0 و سرعت High می‌برد. MX_GPIO_Init را پس از این فراخوانی تکرار نکنید. متغیرهای فرکانس از تنظیم‌ها و ثابت‌ها محاسبه می‌شوند؛ فرکانس‌سنج نیستند.

## ساخت و بررسی

با CMake 3.22 یا جدیدتر، Ninja و arm-none-eabi-gcc، از ریشهٔ هر پروژه:

```text
cmake --preset Debug
cmake --build --preset Debug --clean-first
```

با Python 3 کنار فایل‌های همین بسته:

```text
python verify_clocks_v2.py
python verify_archives_v2.py
```

مدل کلاک 8 دستهٔ بررسی محاسباتی دارد: نسبت‌های پایه، 3 مسیر MCO، مسیر کلاک تایمر APB، مثال تقسیم APB بر 4، مرزهای Flash، رد سقف APB1/HCLK و SysTick. مدل فقط حالت‌های اسمی تعریف‌شده را بررسی می‌کند و اعتبارسنج کامل همهٔ انتخاب‌های PLL یا شبیه‌سازی سیلیکون نیست. قاعدهٔ تایمر ×2 فقط برای مسیر مشتق از APB است؛ منبع مستقل هر تایمر باید جدا بررسی شود. دادهٔ محاسباتی را با اندازه‌گیری برابر نگیرید.

## پیش‌بینی و مشاهده

در کاربرگ، فرکانس و دوره را پیش‌بینی و بعد از پروگرام واقعی ثبت کنید. PA8 و GND را از هدر برد با روش مناسب ابزار متصل کنید؛ شمارهٔ پایهٔ IC شمارهٔ هدر نیست. برای 36 MHz پهنای باند، نرخ نمونه‌برداری و بار پروب را با هدف اندازه‌گیری تطبیق دهید. روی کریستال پروب نگذارید؛ بار پروب می‌تواند خود نوسان‌ساز را تغییر دهد. مقایسهٔ دقت HSI و HSE به مرجع زمانی و عدم قطعیت ابزار و شرایط دما/تغذیه نیاز دارد؛ از تعداد رقم نمایشگر نتیجه نگیرید.

CSS در هر 3 پروژه غیرفعال است. در راه‌اندازی HSE، انتظار HAL به تیک وابسته است؛ اگر HSE آماده نشود HAL_TIMEOUT می‌تواند به Error_Handler برسد. این نمونه بازیابی خودکار ندارد. بحث CSS فقط رفتار شرطی و نیاز به رسیدگی NMI را توضیح می‌دهد؛ خرابی یا بازیابی روی برد آزمایش نشده است.

## شواهد و محدودیت‌ها

در 2026-11-02 هر 3 پروژه با منابع بدون تغییر، GCC 13.2.1 و `-O0 -g3 -Wall -Werror` پاک ساخته شدند و هشدار نداشتند. Flash نمونهٔ HSI برابر 8352 و دو نمونهٔ دیگر 8372 بایت است. RAM هر سه 1600 بایت: data برابر 12، BSS واقعی 48، هم‌ترازی 4، heap حداقل 512 و stack حداقل 1024. این مصرف اوج اجرا نیست.

ZIP منابع و ELF/MAP همان فایل‌های واقعی قبلیِ بررسی‌شده‌اند؛ گزارش‌های ساخت مجدد تازه‌اند. این دو نوع شاهد در metadata جدا ثبت شده‌اند. نسخهٔ تولید CubeMX 6.14.0، پایگاه 6.0.140 و CubeF3 V1.11.6 است. خروجی CMake بررسی شده؛ CubeIDE گرافیکی، پروگرام، اسیلوسکوپ، خطای HSE و CSS آزمایش نشده‌اند. مجوزهای اصلی ST/Arm داخل ZIP منابع حفظ شده‌اند.
